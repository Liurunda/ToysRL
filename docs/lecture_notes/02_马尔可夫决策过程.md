# 第 2 章　马尔可夫决策过程（MDP）

> **本章目标**：掌握 MDP 五元组 $(S, A, P, R, \gamma)$、回报 $G_t$ 与折扣因子，
> 并理解井字棋**如何被形式化为一个 MDP**——尤其是视角归一化与"对手托管"折叠这两个
> 平台级设计，它们是后面所有算法的共同地基。
> **对应代码**：`envs/tictactoe.py`、`envs/wrappers.py`。
> **前置知识**：[第 1 章](01_什么是强化学习.md)的交互循环。

## 2.1 MDP 五元组

强化学习研究的问题被形式化为**马尔可夫决策过程（Markov Decision Process）**，
由五个要素组成（符号约定见[附录 A](附录A_符号表.md)）：

$$(S, A, P, R, \gamma)$$

- $S$：**状态空间**。井字棋中即所有可能棋盘；
- $A$：**动作空间**。井字棋中为 9 个格子 $A = \{0, 1, \dots, 8\}$；
- $P(s'|s,a)$：**转移概率**。在状态 $s$ 执行动作 $a$ 后到达 $s'$ 的概率；
- $R(s,a)$：**奖励函数**。井字棋为稀疏终局奖励 +1 / 0 / −1；
- $\gamma \in [0,1]$：**折扣因子**，衡量未来奖励的"贬值"速度。

智能体的目标是找到一个策略 $\pi$，最大化**期望累计折扣回报**：

$$J(\pi) = \mathbb{E}_\pi\left[ G_0 \right] = \mathbb{E}_\pi\left[ \sum_{k=0}^{\infty} \gamma^k r_k \right]$$

## 2.2 马尔可夫性质

马尔可夫性质：**未来只取决于当前状态，与历史无关**。

$$P(s_{t+1} \mid s_t, a_t) = P(s_{t+1} \mid s_t, a_t, s_{t-1}, a_{t-1}, \dots, s_0, a_0)$$

井字棋天然满足这个性质：棋盘本身就是充分统计量——谁下的第几手、怎么走到这一步的，
只要棋盘一样，未来就一样。这也意味着：**历史信息（第 1 章轨迹表里走过的每一步）
不需要喂给算法，棋盘快照就够。**

> 一个容易混淆的点：自博弈训练（[第 10 章](10_训练范式与评估.md)）时对手会不断变强，
> 环境是**非平稳**的。但这破坏的是"转移概率 $P$ 随时间漂移"，并不破坏"棋盘本身是
> 充分统计量"这一条。马尔可夫性质谈的是状态表示，非平稳谈的是环境漂移——两回事。

## 2.3 回报 $G_t$ 与折扣因子 $\gamma$

**回报（return）** 是从时刻 $t$ 起累计的折扣奖励：

$$G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots = \sum_{k=0}^{\infty} \gamma^k r_{t+k}$$

（记号约定：$r_t$ 是第 $t$ 个决策点执行动作后拿到的奖励。本书统一按代码的
"决策点"口径计步，见[附录 A](附录A_符号表.md)。）

为什么需要 $\gamma < 1$？

1. **数学上**：无限回合下保证 $G_t$ 有限；
2. **语义上**：远期奖励的不确定性更高，应该打折扣——"十步后的一分"不如"一步后的一分"；
3. **实践上**：即便井字棋是有限回合（$\gamma=1$ 也收敛），平台仍默认 $\gamma < 1$
   （表格型 0.9、DQN 0.95、PPO 0.99，见 `configs/default.yaml`）。
   有限回合下 $\gamma<1$ 的额外好处是：**价值传播得更快、并且诱导智能体尽早获胜**
   （拖到第 9 手才赢，奖励会被 $\gamma^k$ 折掉一大截）。

## 2.4 井字棋如何被形式化为 MDP（本章核心）

### 2.4.1 状态：3⁹ 种棋盘与 Canonical 视角归一化

底层棋盘是长度 9 的整型数组（行优先，索引 0–8），X=+1，O=−1，空=0（`envs/tictactoe.py:70-81`）。
原始状态空间有 $3^9 = 19683$ 种数组；去掉"不可能出现的棋盘"（如双方棋子数差超过 1）后，
**合法棋盘共 5478 种**，全部可能对局共 255168 局。这个规模小到可以穷举（这是
Minimax 能保证不败的原因），但已经足以演示"表格 vs 神经网络"的取舍（[第 6 章](06_价值函数近似与DQN.md)）。

平台最重要的状态设计是**视角归一化（canonical observation）**（`envs/tictactoe.py:106-108`）：

```python
def get_canonical_board(self) -> np.ndarray:
    """当前轮到玩家的 canonical 观测: 己方=+1, 对手=-1, 空=0。"""
    return (self.board * self.current_player).astype(np.int8)
```

把棋盘**整体乘以当前玩家的标记**：轮到 X 时返回原棋盘，轮到 O 时返回取反后的棋盘。
效果是——**在智能体眼中，+1 永远是自己，−1 永远是对手，0 是空位**。

为什么要这么做？如果没有视角归一化，同一块棋盘对 X 和对 O 是**两个不同的状态**，
模型得学两遍"这块棋该怎么走"；更糟的是 X 的经验（"我有两个连子该进攻"）完全无法
迁移给 O。归一化之后，X 和 O 共享同一份策略/Q 表/网络——"我有一排两个连子"这个
特征在任何视角下都长得一样。这是本平台所有算法**无需为先后手训练两套模型**的根本原因。

> 注意区分：canonical 归一化解决的是**视角**问题；对称性增强（[第 9 章](09_AlphaZero.md)
> 的 D4 变换）解决的是**棋盘旋转/镜像等价**问题。二者不同，别混。

### 2.4.2 动作：Discrete(9) 与合法掩码

动作空间是 9 个格子（`Discrete(9)`），但并非任何时候都合法——已占的格子不能下。
环境提供掩码（`envs/tictactoe.py:110-112`）：

```python
def get_valid_mask(self) -> np.ndarray:
    return (self.board == 0).astype(np.int8)   # 1=可下, 0=已占用
```

为什么用掩码而不是"让智能体自己学着别下非法格"？因为"哪些格子被占了"是**已知信息**，
不包含任何策略内容。若让智能体靠试错学习，它会浪费大量样本撞墙（撞一次还直接判负）。
掩码 = 把领域知识注入搜索空间，让算法专注于真正的策略博弈。第 4 章会讲掩码如何在
各算法中落地。

### 2.4.3 奖励：稀疏终局奖励与视角翻转

`envs/tictactoe.py:83-101` 的 `step` 返回**刚刚落子一方视角**的奖励：

| 情形 | 落子方奖励 |
| :--- | :--- |
| 落子直接获胜 | +1.0 |
| 棋盘填满平局 | 0.0 |
| 中间步 | 0.0 |
| 非法落子（兜底，正常训练被掩码杜绝） | −10.0 并判负 |

底层环境是"双人轮流"，它只保证"落子方视角正确"。要把奖励换算成**我方视角**，
由 `SingleAgentWrapper` 翻转（`envs/wrappers.py:44-56`）：

```python
def step(self, action):
    obs, r, done, info = self.env.step(action)   # 我方落子, r 为我方视角
    if not done:
        obs, r_opp, done, info = self._opponent_step()  # 对手落子, r_opp 为对手视角
        reward = -r_opp                          # 翻转为己方视角 (对手赢 = 我输)
    else:
        reward = r                               # 己方获胜 +1 / 平局 0
```

一个值得停下来想一秒钟的细节：**我方每一步之后，环境内部其实发生了两次落子**
（我的 + 对手的）。因此我方视角的奖励要么是 0（棋局继续），要么是终局值 ±1/0——
我们永远拿不到"中间态 +1"。这就是第 1 章说的稀疏奖励。

### 2.4.4 转移：把对手"折叠"进环境——单智能体 MDP

MDP 的转移函数要求：执行一个动作 $a$，环境返回**下一决策点** $s'$。
但井字棋是双人轮流游戏，我方落子后还没轮到我。解决方法是平台最重要的包装器
`SingleAgentWrapper`（`envs/wrappers.py:19-56`）：

```text
我方的"一步" = 己方落子 → 若未结束, 对手自动落子 → 返回下一决策点 (轮到我)
```

于是从智能体的视角看，环境变成了一个**标准的单智能体 MDP**：

$$s_t \xrightarrow{a_t} \text{(我落子, 对手落子)} \xrightarrow{} s_{t+1},\ r_t$$

对手是谁，决定了 $P$ 长什么样：

- 对手是 `RandomAgent`：$P(s'|s,a)$ 是均匀随机的；
- 对手是 `HeuristicAgent` / `MinimaxAgent`：$P$ 是确定性的。

**关键认识**：固定对手训练（[第 10 章](10_训练范式与评估.md)）时，我们学的其实是在
"对手策略诱导出的 MDP"里的最优策略，而不是井字棋本身的解。换一个更强的对手，
这个 MDP 就变了——这正是"针对弱对手训练会过拟合"的理论根源。

另外，`reset()` 支持随机分配我方先手/后手（`envs/wrappers.py:33-42`）：若我方执后手，
对手先走一步再返回初始观测 $s_0$。配合 2.4.1 的 canonical 归一化，**一份模型无缝
执先/后手**，训练时每局掷硬币决定先后手，逼模型两个角色都学会。

## 2.5 回合、终局与井字棋的可解性

井字棋是**有限回合（episodic）**任务：最多 9 步必终局（终局即"进入吸收状态"）。
由于总状态数只有 5478，理论上可以穷举博弈树——经典结论是：

> **双方最优时，井字棋必为平局。**

这给了我们一个珍贵的"正确答案"标尺：`MinimaxAgent`（`agents/baselines.py:68-119`）
穷举博弈树、保证绝对不败。任何 RL 算法面对 Minimax 的**不败率（胜+平）达到 100%**，
就意味着它找到了理论最优策略（[第 10 章](10_训练范式与评估.md)会详细展开评估协议）。

## 🧪 实验 2-1：亲手验证视角归一化

在 `tictactoe_rl_arena/` 下运行：

```python
# python - <<'EOF'
import numpy as np
from envs.tictactoe import TicTacToeEnv

env = TicTacToeEnv()
obs = env.reset()                      # X 视角
print("初始观测 (X 视角):", obs)
env.step(4)                            # X 落中心 -> 轮到 O
obs_o = env.get_canonical_board()      # O 视角
print("O 视角观测:       ", obs_o)
print("符号翻转一致?      ", np.array_equal(obs_o, -env.board * 1))
# EOF
```

观察：同一块棋盘，O 看到的观测恰好是 X 视角的相反数——"自己永远是 +1"。

## 2.6 小结

- MDP 五元组 $(S, A, P, R, \gamma)$ 是 RL 的统一语言；
- 回报 $G_t$ 带折扣 $\gamma$ 累加未来奖励，是"长期目标"的数学表达；
- 井字棋形式化的三个关键设计：**canonical 视角归一化**（一份模型执先后手）、
  **合法动作掩码**（注入已知信息）、**对手托管折叠**（双人博弈 → 单智能体 MDP）；
- 井字棋双方最优必平，Minimax 提供"理论最优"标尺。
