# 第 8 章　搜索与规划：MCTS

> **本章目标**：理解"学习 vs 搜索"两条路线的分野，掌握 MCTS 四步循环与 UCT 公式，
> 特别弄懂零和博弈里最易写错的**视角翻转**，并逐行读懂 `agents/mcts.py`。
> **对应代码**：`agents/mcts.py`（全文）。
> **前置知识**：[第 3 章](03_价值函数与Bellman方程.md)的 $Q^*$、[第 4 章](04_探索与利用.md)的探索。

---

## 8.1 学习 vs 搜索：RL 的两大家族

前面所有方法（表格、DQN、PPO）都是**学习型**：通过大量真实对局，把经验"蒸馏"进
参数或表格，**离线攒下知识，在线轻装上场**。MCTS 代表另一家族——**搜索型**：

> 不存任何经验。每走一步棋，**当场**在脑子里模拟几千局，算出哪个动作最靠谱。
> 下完这步，模拟结果随手丢弃。

代价与收益正好颠倒：搜索型**零训练**（没有学习曲线，开局即巅峰），但**每步都要
烧大量算力**。它只需要一件东西：环境的模拟器（`TicTacToeEnv.clone()`，`envs/tictactoe.py:114-119`），
因此也叫"模型无关规划"——知道规则就能玩，不需要任何历史对局。

## 8.2 MCTS 四步循环

MCTS 从当前局面（根节点）出发，反复执行四步（`agents/mcts.py:59-88` 的 `_simulate`）：

```text
            ┌─────────────────────────────────────────────┐
            │  ① Selection: 沿 UCT 公式下降到最有前途的     │
            │     叶子(尚未完全展开的节点)                  │
            └──────────────────┬──────────────────────────┘
                               ▼
            ┌─────────────────────────────────────────────┐
            │  ② Expansion: 从叶子展开一个新子节点          │
            │     (选择一个还没展开过的动作)                │
            └──────────────────┬──────────────────────────┘
                               ▼
            ┌─────────────────────────────────────────────┐
            │  ③ Rollout: 从新节点出发随机落子直到终局,      │
            │     得到真实结果 +1 / 0 / -1                  │
            └──────────────────┬──────────────────────────┘
                               ▼
            ┌─────────────────────────────────────────────┐
            │  ④ Backprop: 把结果沿路径回传, 更新沿途       │
            │     节点的 (N, W, Q), 每上一层翻转一次视角     │
            └─────────────────────────────────────────────┘
```

- **③ Rollout** 就是"随机下到底"：在井字棋这种小棋盘上，随机对局也能提供有用的
  终局信号（对照：围棋里纯随机 rollout 几乎永远输，所以 AlphaGo 后来用网络替代了它，
  见[第 9 章](09_AlphaZero.md)）；
- **④ Backprop** 更新每个节点的统计量：$N$（访问次数）、$W$（累计价值）、
  $Q = W/N$（平均价值）。

跑完 $N_{sim}$ 次模拟后，根节点选**访问次数最多**的动作（`agents/mcts.py:54-56`）：

```python
counts = {a: root.children[a].N for a in valid}
return int(max(counts, key=counts.get))
```

为什么是"访问次数最多"而不是"平均价值最高"？因为访问次数是**双重保险**：
被选得多的动作，要么价值高（利用），要么被探索项反复点名（不确定性高、值得再查），
且大数定律已经用几千次模拟把它验得很扎实（"稳健子节点"）。

## 8.3 UCT：树上的探索-利用平衡

Selection 的核心是 **UCT（Upper Confidence Bound applied to Trees）** 公式
（`agents/mcts.py:90-98`）：

$$a^* = \arg\max_a \Big[ \underbrace{-\,Q(child)}_{\text{利用: 平均价值}} + \underbrace{c \sqrt{\frac{\ln N(parent)}{N(child)}}}_{\text{探索: 访问越少加成越大}} \Big]$$

- 探索项的分母是子节点访问次数 $N(child)$：**没怎么被看过的分支**获得巨大加成，
  逼着搜索雨露均沾；$\sqrt{\ln N / n}$ 的形态来自多臂老虎机的 UCB1 上界理论；
- $c$（`c_uct=1.414 \approx \sqrt{2}$`）是探索强度旋钮：调大 → 更爱"尝鲜"，
  调小 → 更爱"吃老本"。它决定的是**搜索的宽度**，而非对局的输赢。

于是第 4 章的探索-利用困境在这里有了树的版本：UCB 的探索是**定向的**
（只加成没看过的分支），远比 ε-greedy 的均匀随机高效。

## 8.4 零和博弈的视角翻转（最易错的一行代码）

MCTS 的树是双方共用的。每个节点的 $Q$ 都是**"轮到该节点玩家走"的视角**。
父节点轮到 X，子节点就轮到 O——同一局面在双方眼中**价值相反**。
因此所有跨层操作都要**翻转符号**：

**Backprop**（`agents/mcts.py:82-88`）：

```python
v = float(value)              # value 是叶节点玩家的视角
for n in reversed(path):
    n.N += 1
    n.W += v
    n.Q = n.W / n.N
    v = -v                    # 每上一层, 翻转一次视角
```

**Selection**（`agents/mcts.py:93-96`）：子节点的 $Q$ 是对手视角，取负翻回己方：

```python
v = -child.Q + self.c_uct * math.sqrt(log_n / (child.N + 1e-8))
```

**Rollout**（`agents/mcts.py:100-114`）更隐蔽：随机模拟过程中**每落一子视角翻转一次**，
终局检测到的三连可能属于任意一方，必须按翻转次数的奇偶把结果还原到 rollout 起始
玩家的视角：

```python
player = 1                    # +1: 仍是起始玩家视角; -1: 已翻转为对手视角
while True:
    result = state_result(state)
    if result is not None:
        return result * player          # 关键: 乘回起始玩家视角
    action = int(self.rng.choice(empty))
    state, _ = self._apply(state, action)
    player = -player                    # 每走一步翻转一次
```

这三处任何一个符号写反，MCTS 就会把"对手的好棋"当"自己的好棋"学——**越搜越臭**。
零和博弈算法里，"谁的视角"永远是头号 bug 来源（[第 9 章](09_AlphaZero.md)的
AlphaZero 同样如此）。

## 8.5 真实实验结果：零训练，接近完美

MCTS **不训练**，直接跑一轮标准评估（`results/mcts_fixed/summary.json`，
`n_simulations=2000`）：

| | vs Random 胜率 | vs Heuristic 胜率 | vs Minimax 不败率 | 评估耗时 |
| :--- | :--- | :--- | :--- | :--- |
| MCTS（零训练） | 0.92 | 0.0 | **1.00** | 79s |

- 对 Minimax **不败率 100%**——按[第 2 章](02_马尔可夫决策过程.md)的标尺，
  已达到理论最优棋力，而它**一局都没训练过**；
- 对 Heuristic 胜率 0.0：并非它弱，而是**双方都接近最优时井字棋只会平局**
  （先手优势不足以赢下不犯错的对手）。"0 胜率"在这里恰恰是棋力强的证据——
  [第 10 章](10_训练范式与评估.md)会展开这个反直觉点；
- 79s 是"评估 250 局"的总耗时——每步 2000 次模拟的算力账单。作为对照，
  表格型训练只要 2.8s，但棋力差得远：**MCTS 用算力换样本，Q-Learning 用样本换棋力**。

模拟次数是棋力旋钮：`configs/default.yaml` 里 `mcts.n_simulations` 从 2000 降到 50，
棋力会明显下滑（实验 8-1）——搜索型方法的"学习曲线"就是**每步算力 vs 棋力**的曲线。

## 🧪 实验 8-1：算力-棋力权衡曲线

```bash
cd tictactoe_rl_arena
python run_experiment.py --agent mcts          # 默认 2000 次模拟, 直接评估
```

然后改 `configs/default.yaml` 的 `mcts.n_simulations` 为 `50 / 300 / 2000`，
每次改完重跑上面的命令，记录 `results/mcts_fixed/summary.json`：

| n_simulations | 预期 vs Minimax 不败率 | 预期单局耗时 |
| :--- | :--- | :--- |
| 50 | 明显下滑（搜索太浅） | 很快 |
| 300 | 接近但不稳定 | 中等 |
| 2000 | 1.00 | 慢 |

再运行 `python run_experiment.py --agent mcts --viz` 看开局空棋盘的**访问次数热力图**：
中心与角落的访问次数显著高于边格——搜索自己"发现"了角>边>中心的古老棋理，
没有看过任何棋谱。

## 8.6 小结

- 搜索型方法零训练、每步现算，与学习型方法构成"算力 vs 样本"的镜像；
- MCTS = Selection（UCT）+ Expansion + Rollout + Backprop 的反复循环；
- UCT 把多臂老虎机的 UCB 搬上树，探索定向且高效；
- 零和博弈的视角翻转是 MCTS 的头号易错点：backprop 每层取负、selection 取负、
  rollout 按奇偶还原；
- 2000 次模拟的 MCTS 零训练即达理论最优——为下一章"搜索+学习"的联姻埋下伏笔。
