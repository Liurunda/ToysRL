# 第 1 章　什么是强化学习

> **本章目标**：建立"智能体与环境交互"的心智模型，理解试错学习、延迟回报与信用分配
> 三个核心问题，并把它们对应到 `tictactoe_rl_arena` 的代码接口上。
> **对应代码**：`envs/tictactoe.py`（环境）、`agents/base.py`（智能体接口）。
> **前置知识**：无。

## 1.1 三张图：监督学习、无监督学习、强化学习

机器学习的三大家族按"给什么信号"区分：

| | 输入中有什么 | 要学什么 | 典型任务 |
| :--- | :--- | :--- | :--- |
| **监督学习** | 每个样本带正确答案（标签 $y$） | 从 $x$ 预测 $y$ 的映射 | 分类、回归 |
| **无监督学习** | 只有数据本身 | 数据的内在结构 | 聚类、降维、生成 |
| **强化学习** | 只有**评价性的奖励信号** | 在环境中采取**行动**以最大化长期累积奖励 | 下棋、控制、对话 |

区别的关键在"评价"与"指导"：

- 监督学习告诉你**标准答案**：这张图是猫，正确答案为 1，错了就按误差改。
- 强化学习只告诉你**做得好不好**：这步棋走完你赢了（+1），赢了也不告诉你"哪一步赢的"、
  "别的走法会不会赢得更多"。

因此 RL 的本质是：**在不知道标准答案的情况下，通过反复试错、根据奖励信号改进自己的行动策略**。

## 1.2 智能体-环境交互循环

强化学习的形式化起点是一个循环：

```text
         ┌───────────────────────────────────────────┐
         │                   环境                     │
         └────▲──────────────────────────────┬───────┘
      观测 s_t │                             │ 奖励 r_t
              │                             ▼
         ┌────┴──────────────────────────────┬───────┐
         │             智能体 (Agent)         │       │
         └───────────────────────────┬───────┴───────┘
                                     │ 动作 a_t
                                     ▼
```

时间步 $t$ 上发生的事只有三件：

1. 智能体观测到当前**状态** $s_t$；
2. 智能体选择一个**动作** $a_t$；
3. 环境转移到新状态 $s_{t+1}$，并返回一个数值**奖励** $r_t$。

把这个循环对应到井字棋：$s_t$ 是当前棋盘，$a_t$ 是"下在哪一格"，$r_t$ 是这步棋的得分，
$s_{t+1}$ 是（自己与对手走完后）下一轮轮到自己时的棋盘。本章第 1.4 节会完整走一遍。

### 框架对照：循环即代码

`envs/tictactoe.py` 中的环境接口就是这个循环的代码化（`envs/tictactoe.py:78-101`）：

```python
obs = env.reset()                          # 拿到初始状态 s_0
while True:
    action = agent.select_action(obs, ...) # 智能体选动作 a_t
    obs, reward, done, info = env.step(action)  # 环境转移: s_{t+1}, r_t, 是否终局
    if done:
        break
```

`reset()` 返回初始观测；`step(action)` 执行动作并返回 `(下一观测, 奖励, 是否结束, 附加信息)`。
所有 RL 算法的差异都发生在 `select_action` 内部——**环境接口对一切算法是同一套**，
这正是本平台能公平对比七种算法的前提。

## 1.3 试错、延迟回报与信用分配

RL 的三个核心困难，全部可以在井字棋里体会到：

**① 试错学习（trial-and-error）**：智能体不知道哪步是好棋，只能先乱下。
下多了发现"下在角上容易赢、下在边中间容易输"，策略就慢慢变好。
没有标注数据告诉它"这步棋的正解"，只有终局的一锤定音。

**② 延迟回报（delayed reward）**：井字棋的奖励设计是**稀疏的**——
中间每一步的奖励都是 0，只有终局才给 +1（赢）/ 0（平）/ −1（输）。
走第一手时完全不知道这手棋会导向胜利还是失败，可能要等 8 步之后才知道。

**③ 信用分配（credit assignment）**：赢了，是第 1 手立了功，还是第 7 手才救回来？
奖励信号只有一个标量，却要分摊给一路上所有的决策。
解决信用分配是价值函数（第 3 章）与回报回溯（第 5 章）存在的意义。

## 1.4 完整示例：一局井字棋的轨迹

设我方执 X（先手），对手执 O。棋盘索引（行优先）：

```text
 0 | 1 | 2
---+---+---
 3 | 4 | 5
---+---+---
 6 | 7 | 8
```

一局可能的对弈（`r` 为我方视角的奖励）：

| 步 | 轮到 | 动作 | 棋盘（X/O/·） | 我方奖励 r |
| :--: | :--: | :--: | :--- | :--: |
| 1 | 我 X | 0（角） | `X········` | 0 |
| 2 | 对手 O | 1 | `XO·······` | — |
| 3 | 我 X | 4（中心） | `XO··X····` | 0 |
| 4 | 对手 O | 2 | `XOO·X····` | — |
| 5 | 我 X | 8 | `XOO·X···X` → 对角线 0-4-8 三连！ | **+1** |

这一局里我方走了 3 手，**前 2 手奖励全是 0**，第 3 手 +1（获胜由我方最后一手触发；
若对手获胜，我方视角的奖励会被环境翻转成 −1，细节见[第 2 章](02_马尔可夫决策过程.md)）。
所谓"学习"，就是让算法把这 +1 合理地"记账"到第 1、3、5 步（我方第 1、2、3 手）头上——
好棋多记一点，坏棋少记一点。这就是后面 Bellman 方程与 TD 更新在做的事。

## 1.5 强化学习的四个要素

Sutton & Barto 把 RL 系统拆成四个要素，本讲义完全沿用（[附录 A](附录A_符号表.md) 有完整符号表）：

1. **策略（policy）$\pi$**：给定状态，怎么选动作。是智能体的核心，唯一"可改"的东西。
   - 确定性策略：$\pi(s) = a$；
   - 随机策略：$\pi(a|s) = \mathbb{P}(A_t = a \mid S_t = s)$。探索需要随机（第 4 章）。
2. **奖励信号（reward）$r_t$**：环境对动作的即时评价，是**唯一**的外部反馈。
3. **价值函数（value function）$V(s)$ / $Q(s,a)$**：对"长期能拿多少奖励"的预测，
   用来处理延迟回报与信用分配（第 3 章）。
4. **模型（model）**：对环境的模拟器。有模型可以直接推演（第 8 章 MCTS），
   无模型则必须靠真实交互学习（第 5–7 章）。

## 1.6 框架对照：统一智能体接口

`agents/base.py` 定义了所有算法的公共接口（`agents/base.py:39-62`）：

```python
class BaseAgent(ABC):
    def select_action(self, obs, valid_mask, training=True) -> int: ...  # 必须实现
    def observe(self, transition) -> None: ...   # 存入一条经验（默认空实现）
    def update(self) -> dict: ...                # 执行参数/Q 表更新（默认空实现）
    def end_episode(self) -> None: ...           # 回合结束钩子（默认空实现）
```

- `select_action`：策略 $\pi$ 的代码形态。`training=True` 允许探索（如 ε-greedy 随机、
  PPO 按分布采样），`False` 则贪婪/确定（评估与对弈时用）。
- `observe`：拿到一条**转移**（Transition，`agents/base.py:27-36`），包含
  `(obs, action, reward, next_obs, done, 合法掩码)`。表格型算法就地更新，
  DQN 存入回放缓冲，PPO 存入 rollout buffer——"何时学"由各算法自己决定。
- `update`：真正动参数的地方。训练循环每步都调用它，算法内部判断"材料够不够"，
  不够就返回空字典（见第 5–7 章各实现）。
- `end_episode`：一局结束后的清理与收尾（MC 在这里算整局回报、SARSA 在这里补最后一拍）。

这个"选动作 + 收经验 + 更新参数"的三件套接口，能装下从 Q 表到 AlphaZero 的所有算法，
是第 5–9 章反复出现的骨架。

## 🧪 实验 1-1：亲手打印一局轨迹

在 `tictactoe_rl_arena/` 下运行以下脚本（两个随机策略对弈），
体会"中间步奖励全是 0、终局才有 ±1"：

```python
# python - <<'EOF'
import numpy as np
from envs.tictactoe import TicTacToeEnv
from agents.baselines import RandomAgent

env = TicTacToeEnv()
rng = np.random.default_rng(0)
agents = {1: RandomAgent(rng=rng), -1: RandomAgent(rng=rng)}
obs, done = env.reset(), False
t = 0
while not done:
    a = agents[env.current_player].select_action(obs, env.get_valid_mask())
    obs, r, done, info = env.step(a)
    print(f"t={t}: 玩家{env.current_player} 落子 {a}, 奖励={r}, 终局={done}")
    t += 1
print("胜者:", info["winner"])
# EOF
```

观察输出：所有 `奖励=0` 直到最后一拍出现 `奖励=1.0` 且 `终局=True`。

## 1.7 小结

- RL 与监督学习的分野在于**评价性奖励 vs 标准答案**；
- 交互循环（状态 → 动作 → 奖励）是 RL 的原子结构，`reset/step` 是它的代码化；
- 延迟回报与信用分配是 RL 特有的困难，**价值函数**是为解决它们而发明的概念（第 3 章）；
- `BaseAgent` 的 `select_action / observe / update / end_episode` 四接口将贯穿全书。
